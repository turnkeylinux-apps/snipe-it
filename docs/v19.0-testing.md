## Scope and source decision

therefore installs official Snipe-IT v8.6.3 from the maintained upstream Git
repository. The build pins commit
`cfd1ff8413e478a8daab700c15e96c96f93220e2` and tree
`012c6af2f4b2428d4c057b9861a7ab71f2a87e14`, verifies both objects, and retains
the official remote for supervised updates. The release supports PHP 8.4.

PHP, Apache, MariaDB, Redis, Composer, Postfix and the PHP extensions come from
signed Debian Trixie and TurnKey repositories. The disposable dependency probe
installed the production Composer lock on PHP 8.4 and ran `php artisan
--version` successfully before the appliance build.

## Supervised updates

Run the non-destructive check first:

```sh
turnkey-snipe-it-update --check
```

After a verified backup and review of the upstream release notes, apply the
official Snipe-IT Git and migration workflow as root:

```sh
turnkey-snipe-it-update --apply
```

The apply path discovers the current official stable tag and its peeled Git
commit, fetches and verifies that exact tag, then passes the tag to Snipe-IT's
maintained `upgrade.php` with `--branch`. After the application upgrade, it
requires `HEAD` to match the discovered commit before advancing the local
source marker. The upstream workflow installs the locked production Composer
dependencies, migrates the existing database and clears application caches.

## Known limitation

Docker runtime validation does not exercise the installer, kernel, bootloader
or physical hardware. Snipe-IT adds no appliance-specific behavior at those
boundaries, so the validated Core 19 baseline supplies inherited evidence.

## Deferred issues

- The focused acceptance creates and reads a hardware asset. It does not run a
  separate CRUD cycle for licenses, accessories, consumables, components,
  users, suppliers or maintenance records. Those adjacent object types use the
  same authenticated application, API and MariaDB boundaries and are outside
  the high-value main flow.
- LDAP, SAML, SCIM, cloud object storage, external SMTP relays and third-party
  chat integrations require deployment-specific services. The appliance test
  does not provision those optional integrations.
